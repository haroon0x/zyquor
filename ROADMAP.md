# Roadmap

Where Zyquor stands and what is left. `docs/rust-migration.md` is the migration
record; this file tracks the product and the honest state of each piece.

## Where the project is

The TypeScript implementation was retired on 2026-11-08. The product is one
Cargo workspace: `crates/zyquor-*` plus `apps/{api,worker,desktop,cli}`. The
only non-Rust artifact is the React renderer in `apps/web`, kept by the M7
decision and served inside the Tauri webview.

## Landed 2026-11-12

- **Desktop control plane over HTTP.** The Tauri shell injects
  `zyquor_api::DesktopControlPlane` into `AppState`, so the web UI's System
  panel works again end to end: `GET /system/logs`,
  `POST /system/worker/pause`, `POST /system/chrome/close`,
  `POST /system/stop-all`, `POST /system/quit`, `POST /system/restart`, plus
  the `desktop` block and `worker.paused` in `GET /system/status`. Response
  shapes and defaults are ported from the retired `system.ts`; the standalone
  API still answers 404 for the desktop-only routes, as the TS API did without
  `deps.desktopControl`. Covered by `apps/api/tests/desktop_control.rs` and
  the extended `--headless-smoke`.
- **`/system/posting` respects the settings store.** `enablePrepare`,
  `enablePost`, and `autoApproveSourcePackets` round-trip through the process
  settings store instead of returning a hardcoded `false`.
- **CI matches the tree.** The dead pnpm `test` job became the web-renderer
  job (`apps/web`), and `dist-desktop-win` became `desktop-win` (`cargo tauri
  build`, unsigned). A release tag no longer runs Electron packaging scripts
  that no longer exist.
- **`.env` loads again.** Every Rust entry point calls
  `zyquor_core::dotenv::load()`; the port had silently dropped the TS
  `dotenv` import, so `cp .env.example .env` did nothing. Process
  environment still wins.
- **`zyquor start` / `zyquor web` work.** They ran `pnpm --filter @zyquor/web
  dev` from a root pnpm workspace that no longer exists; they now run Vite
  from `apps/web`.
- **Clean checkout builds the desktop bundle.** The Tauri icons were
  gitignored and generated by an undeclared script; they are committed now
  (regeneration lives in `apps/desktop/scripts/` with its own manifest).
- **Docs tell the truth.** `ROADMAP`, `CLAUDE`, `AGENTS`, `README`,
  `docs/architecture`, `docs/development`, `docs/rust-migration`, and the
  shipped `skills/zyquor` skill no longer describe the retired TypeScript
  tree.

## Landed 2026-11-14

- **Generation provider hot-swap.** `PATCH /generation` swaps the live provider
  in place (`LiveGenerationProvider` holds the merged env snapshot + provider
  behind an `RwLock`), persists the saved config, and syncs the desktop
  settings panel. `GET /generation`, `/health`, and `/system/status` read the
  live state; `PATCH /settings` generation keys hot-swap the same way. Covered
  by `apps/api/tests/desktop_settings.rs`.
- **Desktop settings actually persist.** A `DesktopSettingsPlane` is injected
  into `AppState` the same way the control plane is; the Tauri shell implements
  it over `settings.json` (atomic save, env application, autostart re-wiring).
  `GET/PATCH /settings`, `/system/posting`, and the `posting` block of
  `/system/status` all go through it, so toggles survive a restart. The
  standalone API keeps a process-level fallback (documented deviation: TS
  answered 404 for `/settings` without `desktopSettings`).
- **`autoApproveSourcePackets` is consumed.** One shared gate now covers the
  source-packet draft route and the automatic-ingest lane: `enablePost` and the
  stored setting must both allow it, and an unset setting keeps the TS fallback
  (`true`). The standalone dev API honours `POST /system/posting` and
  `PATCH /settings` too, so the GUI toggle works everywhere (deliberate
  post-migration deviation: TS had no settings surface in standalone mode).
- **Storage parity.** `deleteAccount` matches the retired TypeScript table list
  and the legacy null-`text_hash` lookup has a regression test. The TS deletion
  omitted `knowledge_entries`, which failed on the non-cascading FK; that
  reproduction was corrected on 2026-11-17 (see below).
- **Tests.** `parse.rs` gained 13 fixture tests; `zyquor-storage` gained the
  account-deletion and null-hash tests; a new in-process end-to-end HTTP suite
  (`apps/api/tests/e2e_workflow.rs`, 8 tests, no LLM/browser/network) covers
  accounts, draft → select → approve → job, quality-gate rejections, source
  packets, ingest configs, system feedback, history, and generation reads.
- **Tauri code signing documented.** `docs/code-signing.md` is rewritten for
  Tauri v2 (Authenticode vs updater signatures, verification, open decisions)
  and the `desktop-win` CI job has opt-in Authenticode wiring guarded on
  repository secrets; releases stay unsigned until a certificate is chosen.
- **`zyquor outreach`.** New review-only CLI lane that finds live Hacker News
  and Reddit threads, ranks them, and queues human-reviewed answers. No posting
  path, no browser automation (see `docs/outreach.md`).

## Landed 2026-11-17

- **`deleteAccount` cleans knowledge entries.** The port had reproduced the
  retired TypeScript bug where `knowledge_entries` were left behind and the
  non-cascading FK failed the delete and rolled the transaction back; account
  deletion now clears them in the same transaction. Covered by storage tests
  and a new API e2e test.
- **`xai-news` publishes items again.** The adapter captured only the bare
  month from the published-date regex, so `parse_date` always failed and every
  card was dropped. It now captures the full `Month D, YYYY` text; fixture
  tests cover full/short month names, 1-digit days, dedupe, and the blurb
  fallback.
- **Agent native.** Added a stdio MCP server (`zyquor mcp`, 14 default tools:
  status/queue/history reads plus draft → generate → select → screened approve;
  `prepare_job`/`post_job` appear only behind `--allow-browser`/`--allow-post`,
  and posting also needs `confirm:"post"`), a `zyquor status --json` discovery
  command, a project-scoped `.mcp.json`, a repaired `./zyquor` wrapper (fresh
  built binary, else `cargo run`), `docs/agents.md`, and an updated
  `skills/zyquor` (also served as the MCP resource `zyquor://guide`). Protocol
  covered by `apps/cli/tests/mcp_protocol.rs`.
- **Release-signing readiness.** The Tauri updater minisign keypair was
  generated (public key committed at `apps/desktop/updater.pubkey` and in
  `plugins.updater`; private key + password held outside the repo), CI can sign
  updater artifacts and emit `latest.json`
  (`scripts/generate-updater-manifest.py`) when the secrets are configured, and
  `REQUIRE_WINDOWS_SIGNING=true` will fail release tags that would publish
  unsigned installers. `scripts/new-dev-code-signing-cert.ps1` dry-runs the
  Authenticode plumbing with an untrusted self-signed certificate.
- **One auto-approval gate.** The source-packet draft route and the
  automatic-ingest lane share `auto_approve_allowed(enable_post, setting)`; the
  standalone dev API now honours its settings store (GUI toggle + posting
  flag), with unit tests for the gate truth table.

## Live X acceptance (2026-11-17)

The M4 exit criterion is met. With an explicit go-ahead, posting was enabled
for the acceptance window and the full gated path ran against the dedicated
`@haroon0x` profile:

draft (idea) → generate → select → screened approve (`prepare_only`) → worker
prepare (`text_inserted`) → explicit `POST /jobs/:id/post` (`post_clicked` →
`verified`) → permalink + `post_history` row.

Two real posts came out of the run (`.../status/2122621984655072850021` and the
reconciled first attempt `.../status/2122621989483692154`). Posting was turned
back off afterwards and stays off by default. Three browser-flow bugs only
surfaced live and were fixed in the same change set:

- **Session checks on the composer route.** `/compose/post` renders without the
  nav shell, and X's `verify_credentials` fallback now answers 403, so the
  composer-route login guard reported "not logged in" on an authenticated
  session. Session/login checks now run on a home shell page.
- **Chrome relaunch before browser jobs.** With `close_after_prepare` /
  `close_after_post`, the next prepare/post found CDP dead; both paths now call
  `ensure_browser_cdp` first (parity with the TS `autoLaunchCdp`).
- **Post-click permalink verification.** The first accepted post was published
  but the job failed because the permalink could not be read from the compose
  page. Verification now falls back to the author's profile (or the reply
  thread), reloading a few times — a successful post can no longer be recorded
  as failed.

## What is left

Only one item is left, and it needs a human purchase/identity step:

1. **Tauri code signing certificate.** Everything except the certificate
   itself is in place (2026-11-17): docs, opt-in secret-guarded Authenticode CI,
   the generated updater keypair (public key committed, private key held
   offline), signed updater artifacts + `latest.json` generation in CI, and a
   `REQUIRE_WINDOWS_SIGNING` enforcement toggle. The remaining human steps are:
   choose/buy a CA-issued code-signing certificate, add the CI secrets (PFX,
   password, updater key + password), set `REQUIRE_WINDOWS_SIGNING=true`, and
   run one signed release on the Windows runner. Releases stay unsigned until
   then.
