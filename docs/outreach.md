# Outreach: find threads, review answers, never post

`zyquor outreach` is a research and review lane for answering live Hacker News
and Reddit threads where someone describes the pain a repo solves. It is
deliberately outside the X pipeline: it opens no browser, creates no post job,
and has no code path to `ZYQUOR_ENABLE_BROWSER_POST`.

The intent is an honest answer with the repo as the artifact, one link maximum,
and a human decision before anything is sent.

## Commands

```bash
# 1. find and rank live threads
cargo run -p zyquor-cli -- outreach find \
  --profile data/outreach/profiles/herald.json --limit 8

# optional: only one source
cargo run -p zyquor-cli -- outreach find --profile <path> --hn-only
cargo run -p zyquor-cli -- outreach find --profile <path> --reddit-only --live-only

# 2. write data/outreach/runs/<run-id>/drafts.json, then queue it
cargo run -p zyquor-cli -- outreach queue --run <run-id>
cargo run -p zyquor-cli -- outreach review
cargo run -p zyquor-cli -- outreach list

# 3. after posting manually, record the comment and check it later
cargo run -p zyquor-cli -- outreach mark-sent --id <item-id> --url <comment-url>
cargo run -p zyquor-cli -- outreach verify
cargo run -p zyquor-cli -- outreach skip --id <item-id> --reason "..."
```

## What `find` does

- Reuses the existing `RedditAdapter`, the new `RedditCommentsAdapter`, and the
  `HackerNewsSearchAdapter` (comment mode) through the normal `Fetch` seam.
- Tries direct Reddit first. When Reddit blocks the request (for example HTTP
  403 from a datacenter IP), it falls back to the public Arctic Shift archive
  for comments, post titles, subreddit rules, and comment trees. The run's
  `access.reddit` field says which path was used.
- Ranks by recency, exact-pain phrases, whether the title is actually about the
  topic, whether the post is a question/advice thread rather than news,
  comment activity, the subreddit's self-promotion rule, and mod removal
  signals in the thread.
- Rejects launch posts, self-promo comments, removed/deleted comments, hiring
  megathreads, Show HN launches, locked threads, and threads where the repo is
  already mentioned.
- Writes `candidates.json`, `report.md`, and `draft_prompt.md` under
  `data/outreach/runs/<run-id>/`.

The ranker is intentionally conservative. A candidate that is not `queueable`
stays in the report for context but cannot be queued.

## Profile

A profile is a small JSON file. See `data/outreach/profiles/herald.json` and
`data/outreach/profiles/zyquor.json`.

```json
{
  "repo": "haroon0x/herald",
  "name": "Herald",
  "one_liner": "A local-first communication agent...",
  "pains": ["prompt injection", "sent without approval"],
  "keywords": ["email", "inbox", "maildir", "agent", "draft"],
  "pain_groups": [
    ["email", "inbox", "mail", "maildir"],
    ["agent", "assistant", "llm", "draft"],
    ["approval", "privacy", "send", "triage"]
  ],
  "exact_pains": ["prompt injection", "draft replies", "maildir"],
  "title_groups": [
    ["email", "inbox", "mail", "gmail"],
    ["agent", "assistant", "draft", "model", "local"]
  ],
  "reddit_queries": [
    {"subreddit": "LocalLLaMA", "term": "thunderbird"},
    {"subreddit": "selfhosted", "term": "inbox"}
  ],
  "hn_queries": ["email agent", "draft replies", "local email"],
  "utm": {"campaign": "herald-thread-test-w1"},
  "voice": "Lowercase, concrete, first person...",
  "link_policy": "One link, last line, UTM. Disclose."
}
```

`pain_groups` are AND-of-OR gates over the comment text. `title_groups` are the
same over the thread title. This is what keeps "email" + unrelated "agent" from
ranking as a fit. `exact_pains` are phrase hits that boost the score and are
required for a queueable item unless the title is a direct question.

## Drafts and queue

Drafts are written by a human or an agent, not generated by the command. The
queue validates each one:

- 120–4000 characters;
- exactly one URL (and it must be the repo URL with UTM parameters);
- a disclosure phrase ("I built", "I'm the author", "my repo");
- one-sentence hypothesis;
- the candidate is still queueable, under 7 days old, and the repo is not
  already mentioned in the thread;
- no template openers ("great question", "hey OP").

Queued items live in `data/outreach/outreach.sqlite`, in their own table. The
review output is also written to `data/outreach/review.md` with the target
thread, parent comment, rules excerpt, removals, hypothesis, reply text, link,
and a manual-send checklist.

## Safety invariants

- No autoposting to Reddit, Hacker News, or X.
- No alt accounts, no engagement loops, no follow/like/upvote requests, no DMs.
- No browser automation for the reply itself; you read the thread and send it.
- One link maximum, disclosed affiliation, and no link when the repo does not
  fit the person's actual setup.
- The queue has no `approve` path and no post job. It cannot enqueue an X post.

## Limitations

- Reddit may block the machine. The archive fallback is read-only and can lag;
  run the finder on your own machine if you need the live JSON API.
- Subreddit rules are read from the rules feed, not interpreted by an LLM. A
  rule can still be enforced by a human mod in ways the feed does not show.
  Read the thread and the sidebar before sending.
- The ranker is a heuristic. It is a candidate generator, not an authority; the
  human review is the gate.
