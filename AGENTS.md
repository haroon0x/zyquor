# Project rules

- **The project is migrating from TypeScript to Rust.** The target is a Cargo workspace at the repo root (`crates/zyquor-*`, `apps/api`, `apps/worker`, `apps/desktop`). See `docs/rust-migration.md` for the crate layout, milestone order, and parity rules. New code should be written in Rust where the owning crate already exists on that branch; do not add new TypeScript packages. The TypeScript implementation stays runnable until each Rust crate reaches parity, so keep both green during the transition.
- Rust toolchain: install with `rustup` (stable). Verify with `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`.
- Do not delete a TypeScript package or script until its Rust replacement passes the parity harness described in `docs/rust-migration.md`.
- Never run the Electron desktop app inside WSL. Start it from native Windows instead.
- If you have the optional Graphify code-graph tool installed, prefer it over grep/read: `graphify query "<question>"`, `graphify path "A" "B"`, `graphify explain "Symbol"`. Fall back to grep/read otherwise. It is local tooling; `graphify-out/` is gitignored. After structural code changes, refresh the graph with `graphify update . --no-cluster` (zero cost, no API key).
- Local dev ports: the API listens on 3000 by default. If that port is taken, run it with `ZYQUOR_API_PORT=3001` and start the web UI with `ZYQUOR_API_URL=http://127.0.0.1:3001 pnpm --filter @zyquor/web dev` so the `/api` proxy matches.
- Posting is disabled by default. `ZYQUOR_ENABLE_BROWSER_PREPARE=1` / `ZYQUOR_ENABLE_BROWSER_POST=1` enable the browser lanes; enabling them, or running the reply/post loops, requires an explicit human ask. Failed external post jobs are never auto-retried.
- Each X account runs on its own Chrome profile and its own remote-debugging port under `profiles/<handle>`. Jobs for different accounts run at the same time; there is no one-account-at-a-time limit. `posting-chrome.json` keeps one small record per profile, not one record for the whole app. The old single-account lock — the `GET /browser/active` check in `apps/worker/src/index.ts:341` and the `Only one account can post at a time` check in `apps/api/src/lib/post-browser-job.ts:118` — is gone. Each account still has its own limits: daily post limit, quiet hours, gap between posts, and one running browser job at a time for that account.
- Persistence is SQLite only (`node:sqlite`); there is no JSON fallback.
